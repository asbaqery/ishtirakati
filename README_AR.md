# ضمان 🛡️

ادفع لحسابات الإنستغرام والمشاريع المنزلية بأمان: المبلغ **ينحجز** على بطاقة المشتري، وما ينتقل للبائع إلا لما المشتري يأكد إنه استلم طلبه.
مشروع Day 6–7 في دورة Web with AI (ثيم FinTech).

- الموقع: https://daman-kw.vercel.app
- الكود: https://github.com/asbaqery/daman

## المشكلة والحل
المشتري يخاف يحول لحساب ما يعرفه، والبائع يخاف يشحن قبل لا يضمن الدفع. «ضمان» يحجز المبلغ بدل ما يحوله:
1. البائع يسوي صفقة (المنتج والسعر) وياخذ رابط يرسله بالواتساب.
2. المشتري يفتح الرابط، يسجل دخول، ويدفع بالبطاقة. **المبلغ ينحجز** (Stripe بوضع التجربة، `capture_method: manual`).
3. البائع يشوف «المبلغ محجوز» ويعلّم «تم الشحن».
4. المشتري يأكد الاستلام فينسحب المبلغ للبائع، أو يلغي قبل الشحن فينفك الحجز وما ينخصم شي.

## ميزات الـ MVP
- تسجيل دخول بالإيميل للبائع والمشتري.
- صفقة جديدة برابط ينرسل بالواتساب.
- دفع بحجز المبلغ بدون سحبه.
- «تم الشحن» من البائع بعد ما ينحجز المبلغ.
- تأكيد الاستلام (سحب المبلغ) أو الإلغاء (فك الحجز).
- صفحة الصفقة تبين الحالة لكل طرف خطوة بخطوة، وتتحدث بروحها.

## كيف تشتغل
| الجزء | المكان |
|---|---|
| الواجهة | React + Vite + TypeScript + Tailwind على Vercel (`vercel.json` يمنع 404) |
| الدخول | Supabase Auth (إيميل وكلمة مرور، مع تأكيد الإيميل) |
| البيانات | جدول `deals` في Supabase مع RLS |
| الدفع | 3 Edge Functions: `create-checkout` و`deal-action` و`stripe-webhook` |

### الأمان
- المتصفح يقرأ صفقاته ويضيف صفقة بس. ما يقدر يغير الحالة ولا يحط نفسه مشتري ولا يلمس بيانات الدفع (صلاحيات أعمدة + RLS).
- «تم الشحن» وإلغاء الصفقة غير المدفوعة عن طريق دوال `SECURITY DEFINER` تتحقق إن المستخدم هو البائع.
- حالة «المبلغ محجوز» تجي **بس** من Webhook موقّع من Stripe، مو من فتح رابط النجاح.
- الصفقة تنحجز لمشتري واحد وقت الدفع (35 دقيقة)، والدفع الزايد أو اللي يوصل متأخر ينفك حجزه تلقائيًا.
- إلغاء المشتري يحجز الصف أول، فما يتسابق مع «تم الشحن».
- مفاتيح Stripe السرية في Supabase Secrets بس.

### العملة
حساب Stripe التجريبي ما يدعم الدينار، فالموقع يعرض بالدينار ويحصّل بالدولار بسعر ثابت: 1 د.ك = 3.25 دولار.

## المتغيرات ووين تروح
| الاسم | المكان | الوصف |
|---|---|---|
| `VITE_SUPABASE_URL` | Vercel و`.env.local` | رابط مشروع Supabase |
| `VITE_SUPABASE_ANON_KEY` | Vercel و`.env.local` | المفتاح العام (publishable) |
| `SITE_URL` | Supabase Secrets | `https://daman-kw.vercel.app` (روابط العودة وCORS) |
| `STRIPE_SECRET_KEY` | Supabase Secrets بس | مفتاح `sk_test_` |
| `STRIPE_WEBHOOK_SECRET` | Supabase Secrets بس | `whsec_` من Webhook وضع الاختبار |

## الخطوات اليدوية
1. شغّل `supabase/migrations/20261114000000_deals.sql` في SQL Editor.
2. انشر الدوال الثلاث (`supabase/functions`)، وطفّ «Verify JWT» لأنها تتحقق بنفسها. في هذا المشروع انشرت من محرر لوحة Supabase بعد دمج ملفات `_shared` داخل كل دالة.
3. Stripe (Test mode) ← Webhooks: العنوان `https://<ref>.supabase.co/functions/v1/stripe-webhook`، والأحداث: `checkout.session.completed` و`checkout.session.expired` و`payment_intent.canceled` و`payment_intent.succeeded`.
4. حط الأسرار الثلاثة في Supabase Secrets.
5. في Supabase Auth ← URL Configuration: Site URL هو رابط الموقع، وأضف `https://daman-kw.vercel.app/**` لروابط الرجوع.
6. للتجربة: بطاقة `4242 4242 4242 4242`، أي تاريخ مستقبلي، وأي 3 أرقام.

## حدود معروفة
- البنك يحجز المبلغ لمدة 7 أيام تقريبًا. إذا ما تأكد الاستلام خلالها، الحجز ينفك تلقائيًا والصفقة تصير «انتهت مدة الحجز».
- النزاعات وتحويل المبلغ لحساب البائع البنكي في «الرؤية»، مو في الـMVP.
- تأكيد الإيميل شغال، وخدمة الإيميل المجانية في Supabase ترسل بس لإيميلات أعضاء المشروع. عشان يسجل أي أحد لازم SMTP خاص.
- حساب Stripe التجريبي مشترك مع مشروع R3B STORE، وكل Webhook يتجاهل أحداث المشروع الثاني.
